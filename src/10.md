# 10장. FAIR 원칙과 데이터 개방·재사용성 (10주)

## 10.1 FAIR 원칙 개관

FAIR는 2016년 윌킨슨(Wilkinson) 등이 제안한 데이터 관리·스튜어드십 원칙으로, 데이터가 인간과 기계 모두에게 **찾을 수 있고(Findable), 접근 가능하고(Accessible), 상호운용되며(Interoperable), 재사용 가능(Reusable)**해야 함을 15개 세부 원칙으로 제시한다[1].

### 15개 세부 원칙을 아카이브 말로 옮기면

FAIR를 네 글자로만 기억하면 쓸 수 없다. 실제로 점검할 수 있는 단위는 그 아래 15개 세부 원칙이다. 오른쪽 칸이 자가진단의 질문이 된다.

| | 원칙 | 아카이브에서 뜻하는 것 | 점검 질문 |
| --- | --- | --- | --- |
| **F1** | (메타)데이터에 전역 고유·영구 식별자를 부여한다 | 기술 단위와 디지털 사본에 DOI·ARK 같은 PID를 붙인다. 관리번호는 기관 안에서만 통하므로 F1을 충족하지 못한다 | 우리 기록을 가리키는 주소를 10년 뒤에도 쓸 수 있는가 |
| **F2** | 데이터를 풍부한 메타데이터로 기술한다 | 기술규칙에 따른 기술. **아카이브가 가장 잘하는 항목** | 건 단위까지 기술되어 있는가 |
| **F3** | 메타데이터가 자신이 기술하는 데이터의 식별자를 명시한다 | 목록 레코드 안에 원문 파일의 식별자가 들어 있어야 한다 | 목록만 받은 사람이 원문을 찾아갈 수 있는가 |
| **F4** | (메타)데이터를 검색 가능한 자원에 등록·색인한다 | 기관 검색창만이 아니라 외부 검색엔진·통합포털·OAI-PMH 수확 대상이 되어야 한다 | 구글에서 우리 기록이 나오는가 |
| **A1** | 식별자로 표준 통신 프로토콜을 통해 가져올 수 있다 | 주소를 누르면 실제로 열려야 한다 | 식별자가 죽은 링크는 아닌가 |
| **A1.1** | 그 프로토콜은 개방·무료이며 누구나 구현할 수 있다 | HTTP(S)·OAI-PMH·IIIF. 전용 뷰어로만 열리는 자료는 미충족 | 특정 프로그램을 깔아야만 볼 수 있는가 |
| **A1.2** | 필요한 경우 인증·인가 절차를 허용한다 | **비공개 기록도 FAIR할 수 있는 근거 조항.** 인증 절차가 명시되어 있으면 충족 | 제한의 사유와 신청 경로가 적혀 있는가 |
| **A2** | 데이터가 더 이상 제공되지 않아도 메타데이터는 접근 가능하다 | **폐기·이관·멸실된 기록의 기술은 남긴다.** 아카이브의 오랜 원칙이 그대로 FAIR 항목이 되어 있다 | 없어진 기록의 흔적이 목록에 남아 있는가 |
| **I1** | 지식표현을 위한 형식적·공유된 언어를 쓴다 | RDF·XML·JSON 같은 기계가독 형식. PDF 검색도구는 미충족 | 사람이 옮겨 적지 않고 기계가 읽을 수 있는가 |
| **I2** | FAIR한 어휘를 쓴다 | 기관 자체 용어가 아니라 공표된 표준 어휘·전거·시소러스(6.2.3, 11장) | 우리 용어집에 식별자가 있고 공개되어 있는가 |
| **I3** | 다른 (메타)데이터에 대한 **관계가 밝혀진** 참조를 포함한다 | 단순 링크가 아니라 **어떤 관계인지**를 밝힌 연결. RiC가 관계를 개체로 다루는 이유(11.2.2) | "관련 자료"라고만 적혀 있지 않은가 |
| **R1** | 정확하고 관련 있는 속성으로 풍부하게 기술한다 | F2와 겹치되 **재사용자의 관점**에서 본다 — 이 데이터를 처음 보는 사람이 쓸 수 있는가 | 맥락을 모르는 사람이 오독할 여지가 있는가 |
| **R1.1** | 명확하고 접근 가능한 이용 라이선스와 함께 공개한다 | KOGL·CC를 **기계가 읽을 수 있는 형태로**. "출처 표시 후 이용 가능"이라는 문장만으로는 부족하다 | 라이선스가 데이터 필드에 들어 있는가 |
| **R1.2** | 상세한 출처(provenance)와 연결한다 | **출처주의 그 자체.** 생산자·생산 맥락·이관 이력·처리 이력 | 누가 왜 만들었고 어떤 손을 거쳤는지 적혀 있는가 |
| **R1.3** | 해당 분야의 커뮤니티 표준을 충족한다 | ISAD(G)·NAK·EAD·RiC. 자체 포맷은 미충족 | 다른 기관이 우리 데이터를 바로 읽을 수 있는가 |

이 표를 쭉 읽으면 **아카이브가 이미 잘하는 것과 전혀 못하는 것이 뚜렷이 나뉜다.** F2·A2·R1.2는 기술규칙이 백 년 넘게 해 온 일이고, F1·F4·I1·I2·I3는 대부분의 기관에서 비어 있다. 즉 FAIR 전환의 과제는 기술을 더 자세히 쓰는 일이 아니라 **이미 쓴 기술을 식별자와 표준 어휘에 묶어 기계가 읽게 하는 일**이다.

FAIR가 연구데이터를 염두에 두고 만들어졌다는 점도 기억해야 한다. 항목마다 데이터셋 단위의 식별자와 API를 전제하므로, **건 단위 수백만 건을 다루는 기록관에 그대로 적용하면 F1부터 비현실적이 된다.** 어느 층위(퐁·시리즈·컬렉션·건)에 식별자를 부여할 것인가를 먼저 정하는 것이 현실적인 출발점이다.

주의할 점: FAIR는 '무조건 개방(open)'이 아니다. A 원칙은 인증·인가 절차를 거친 접근을 허용하므로, "닫혀 있더라도 접근 절차가 투명하면" 충족될 수 있다. 이는 비공개 기록이 많은 아카이브에 중요한 함의를 갖는다 — 메타데이터는 공개하되 원문 접근은 통제하는 설계가 FAIR와 양립하며, 7장의 접근 제한 논리와 9장의 '숨은 기록' 문제를 동시에 완화한다[2].

## 10.2 아카이브에 적용하기

아카이브는 오래전부터 FAIR의 상당 부분(출처 기술, 표준 메타데이터)을 실천해 왔다[3]. 그러나 다음 영역은 과제로 남아 있다.

1. **영구 식별자**: 기술 단위·디지털 사본에 대한 PID(DOI, ARK 등) 부여와 인용 지원
2. **기계가독 메타데이터**: 검색도구를 PDF가 아닌 구조화 데이터(EAD·RiC-O RDF·CSV)로 개방
3. **API**: 목록·원문에 대한 공개 API 제공(OAI-PMH, IIIF, REST/SPARQL)
4. **라이선스 명시**: KOGL·CC 표시로 재사용 조건을 기계가독형으로 제공
5. **데이터로서의 컬렉션(collections as data)**: 연구자가 대량 분석(텍스트마이닝, AI 학습)에 쓸 수 있는 데이터셋 단위 제공

한국의 「공공데이터의 제공 및 이용 활성화에 관한 법률」과 공공데이터포털은 기록 메타데이터 개방의 제도적 기반이며, 국가기록원 목록 데이터 등이 개방 대상이 되어 왔다.

국내 기록학에서는 김학래(2021)가 FAIR를 디지털 아카이브 설계·평가의 틀로 도입하고 성숙도 평가 프레임워크를 제안했으며[5], 이를 적용해 국내 디지털 아카이브 69개를 평가한 후속 연구는 FAIR 평균 점수가 50.43점에 그치며 특히 상호운용성과 재사용성이 매우 낮다는 사실을 실증했다[6]. 위의 다섯 과제가 국내 현장에서 여전히 미해결 상태임을 수치로 확인해 주는 셈이다. 상호운용성을 지식그래프로 구현해 개선한 사례는 11장에서 다룬다.

### 10.2.1 무엇으로 잴 것인가: FAIR 측정 도구

FAIR는 원칙이지 점수표가 아니다. 점수를 내려면 지표와 판정 절차를 갖춘 도구가 따로 필요하고, 지난 10년간 여럿이 만들어졌다. 아래는 2026년 11월에 직접 접속해 확인한 것이다[7].

| 도구 | 무엇을 재나 | 방식 | 필요한 입력 |
| --- | --- | --- | --- |
| **RDA FAIR Data Maturity Model** | 41개 지표에 대한 기관 자체 성숙도(0~4) | **전면 수동**(스프레드시트) | **없음** — PID·API 불필요 |
| **F-UJI** | 데이터셋 1건의 FAIR 성숙도 | 완전 자동 | DOI 또는 랜딩페이지 URL |
| **FAIRshake** | 공동체가 정의한 rubric에 대한 적합도 | 자동·수동 선택 | 객체 URL + rubric |
| **FAIR Evaluator** | 성숙도 지표(MI)와 준수 테스트 | 완전 자동 | 메타데이터 레코드의 GUID, ORCID |
| **FAIR Enough** · **FAIR Checker** | URI 하나에 대한 자동 평가 | 자동 | 자원 URI |
| FAIRassist | 평가 도구 레지스트리(평가기가 아님) | — | — |

**구분의 기준은 자동이냐 수동이냐다.** 자동 평가기는 랜딩페이지에서 schema.org·DataCite 같은 기계가독 메타데이터를 긁어 판정한다. 그것이 없는 기록관 사이트를 넣으면 **거의 모든 항목이 0점으로 나온다.** 그 0점은 컬렉션의 상태가 아니라 **평가 도구의 입력 조건**을 말해 줄 뿐이다. 자동 점수를 기관 평가에 그대로 쓰면 안 되는 이유가 여기 있다.

**기록관이 먼저 쓸 것은 RDA 모델이다.** RDA 작업반이 2020년 확정한 권고안으로, 지표 41개가 Findable 7 · Accessible 12 · Interoperable 12 · Reusable 10으로 나뉘고, 각 지표에 **필수(20) · 중요(14) · 유용(7)**의 우선순위가 붙어 있다. 평가자는 지표마다 0(해당 없음)부터 4(완전 구현)까지를 고르고, 그 결과로 기관은 0~5단계 중 하나를 받는다. Zenodo에 자체평가 스프레드시트가 첨부되어 있어 그대로 내려받아 쓸 수 있다. 전면 수동이라 DOI도 API도 필요 없다는 점이 결정적이다. 0~4 척도가 **"아직 못 했다"와 "계획 중이다"를 구분**해 주므로 평가표가 그대로 개선 계획 문서가 된다.

> **눈여겨볼 것 하나.** RDA 모델의 **Interoperable 영역에는 필수 지표가 하나도 없다.** 어휘·온톨로지 정합성은 달성 난도가 높다고 보아 중요·유용으로 내려놓은 것이다. 국내 실증 연구에서 상호운용성 점수가 가장 낮게 나온 것(요약 4)이 한국만의 문제가 아니라는 뜻이기도 하고, 동시에 **"지금 당장 거기부터 하라"는 요구는 국제적으로도 하지 않는다**는 뜻이기도 하다.

DOI가 붙은 소수 자원이 있다면 거기에 F-UJI를 한 번 돌려 **수동 평가가 놓친 기계가독성 항목을 교차 확인**하는 것이 좋다. 순서는 수동이 먼저고 자동이 보조다.

**기록관 전용 도구는 아직 없다.** 가장 가까운 것이 코스터와 바우테르선빈트하우어의 「도서관·기록관·박물관 컬렉션을 위한 FAIR 원칙」(2018)으로, 요구사항을 **객체 · 메타데이터 · 메타데이터 레코드**의 세 층위로 나누고 컬렉션별 평가표(scorecard)를 쓰라고 권한다. 이들이 짚은 마찰 지점은 그대로 국내 현장의 것이다 — 전역 영속식별자가 없고 시스템 내부 식별자는 시스템을 옮기면 끊어진다, API와 일괄 내려받기가 없다, 전거 식별자를 기술 요소에 적지 않는다, 벤더 계약과 초상권이 재이용을 제약한다. **FAIR가 메타데이터의 장기 접근은 다루면서 객체의 보존은 다루지 않는다는 공백**도 이들이 지적한 것이다.

국내 연구들은 자체 도구를 만들어 썼다. 김학래(2021)가 디지털 아카이브용 성숙도 평가 프레임워크를 제안했고, 박하람 외(2024)는 탐색성·접근성·상호운용성·재사용성 네 관점의 평가 방법론으로 69개 아카이브를 채점했다(평균 50.43점). **이 장의 실습은 RDA의 지표 구조를 15개 원칙 단위로 간략화한 것**이며, 실제 기관 평가를 수행한다면 RDA 스프레드시트를 쓰는 편이 비교 가능성 면에서 낫다.

### 10.2.2 점수 대신 선언: FIP(FAIR 이행 프로파일)

진단표는 "몇 점인가"를 묻는다. 그런데 정작 다른 기관이 궁금해하는 것은 **"그래서 당신들은 무엇을 쓰는가"**다. 이 질문을 정식 형식으로 만든 것이 **FIP(FAIR Implementation Profile, FAIR 이행 프로파일)**다. FIP는 한 공동체가 15개 원칙 각각에 대해 **지금 쓰는 자원을 명시적으로 선언**해 둔 문서이며, 그 구조는 FIP 온톨로지로 정의되어 있다[9]. 핵심은 셋이다.

**① 원칙마다 질문이 있고, 데이터용과 메타데이터용이 나뉘어 있다.** F1-D는 "데이터셋에 어떤 전역 고유·영구·해석가능 식별자를 쓰는가"를 묻고, F1-MD는 같은 질문을 메타데이터 레코드에 대해 묻는다. A1.1-MD는 "메타데이터에 어떤 표준 통신 프로토콜을 쓰는가", A2는 "어떤 메타데이터 장기보존 계획을 쓰는가"를 묻는다. **기록관에는 이 구분이 특히 쓸모 있다.** 목록은 공개하고 원문 접근은 통제하는 운영(10.1의 A1.2)이 한 칸에 뭉뚱그려지지 않고 두 줄로 따로 적히기 때문이다.

**② 답은 의견이 아니라 자원이다.** 각 질문의 답은 정해진 유형의 자원 중에서 고른다 — F1은 식별자 서비스, F2는 메타데이터 스키마, F3은 메타데이터–데이터 연결 스키마, F4는 레지스트리, A1.1은 통신 프로토콜, A1.2는 인증·인가 서비스, A2는 메타데이터 보존 정책, I1은 지식표현 언어, I2는 구조화 어휘, I3은 시맨틱 모델·크로스워크, R1.1은 데이터 이용 라이선스, R1.2는 출처 모델이다. 이들을 **FER(FAIR-Enabling Resource)**라 부른다. "노력하겠다"로는 칸을 채울 수 없고 **쓰는 것의 이름을 대야 한다**는 점이 이 형식의 요체다.

**③ 현재와 계획을 같이 적는다.** `declares-current-use-of`(지금 쓴다), `declares-planned-use-of`(쓰겠다), `declares-planned-replacement-of`(바꾸겠다), `declares-planned-development-of`(직접 만들겠다) 네 가지로 선언하고, `considerations`에 **그렇게 고른 이유**를 적는다. 작성된 FIP는 나노퍼블리케이션으로 발행되어 Nanodash에서 열람할 수 있다 — **FAIR 선언 자체가 FAIR하게 발행되는** 구조다.

> **이것이 평가표와 다른 점.** 진단표의 '미충족'은 부채이고 FIP의 '계획 중'은 설계다. 같은 사실을 적지만 문서의 성격이 다르다. 10.2.1에서 RDA 모델의 0~4 척도가 "아직 못 했다"와 "계획 중이다"를 구분해 준다고 했는데, FIP는 그 구분을 **문서의 형식 자체로** 끌어올린 것이다. 15.5절에서 다룰 문제 — 평가 보고서가 보고로 끝나고 아무것도 바뀌지 않는다 — 에 대한 하나의 대답이기도 하다.

국내 기록관이 FIP를 작성한다면 어느 칸이 빌지는 짐작할 수 있다. **I 영역(I1 지식표현 언어, I2 구조화 어휘, I3 시맨틱 모델)과 F1(영구 식별자), R1.1(라이선스)**이다. 10.2절 첫머리의 다섯 과제와 정확히 같은 자리다. 반대로 **R1.2(출처 모델)는 바로 채울 수 있다** — 출처주의와 기술규칙이 이미 그 자리에 있기 때문이다. 11장의 RiC-O는 I1·I3 칸에 적어 넣을 수 있는 몇 안 되는 국제 표준이다.

이 체계를 관리하는 GO FAIR 재단은 **3PFF(Three-Point FAIRification Framework)**라는 실행 틀과 자격 훈련·인증 체계도 운영한다. FAIR가 '좋은 말'에서 **산업적 실무 체계**로 옮겨 가고 있다는 징후이며, 연구비 사업과 공공 정보화 사업의 제안 요건에 FAIR가 들어가기 시작했다는 뜻이기도 하다. 기록관이 그런 사업의 수행기관이 되는 순간, **"우리는 FAIR를 지향한다"가 아니라 "우리는 F1에 ARK를, I1에 RDF를 쓴다"고 적어야** 한다.

## 10.3 FAIR의 균형추: CARE 원칙

CARE(Collective benefit, Authority to control, Responsibility, Ethics)는 선주민 데이터 거버넌스를 위해 제안된 원칙으로, 데이터 개방이 공동체에 미치는 영향과 통제 권한을 강조한다[4]. **CARE에는 측정 도구가 없다.** 캐럴 등은 2021년 논문에서 "현재 어떤 연구 프로젝트가 CARE 원칙을 충족하는지 판정하는 절차는 존재하지 않는다"고 명시하고, FAIR 성숙도 모델을 본떠 CARE 성숙도 모델을 만드는 것을 다음 과제로 제안했다[8]. 실무에서 거론되는 TK 레이블(Local Contexts), 무쿠르투(Mukurtu), 응아 티캉아 파이헤레, OCAP은 모두 **평가 척도가 아니라 기술·접근 통제 장치**다. 이 비대칭 자체가 논점이다 — 잴 수 있는 것은 점수가 되어 보고서에 오르고, 잴 수 없는 것은 선의에 맡겨진다. 10.2.1의 FAIR 점수표를 쓸 때 이 사실을 함께 적어 두어야 한다. 식민지 기록, 소수자·피해자 관련 기록의 데이터화에서 FAIR(개방·재사용)와 CARE(맥락·통제)는 긴장 관계에 놓일 수 있으며, 두 원칙의 통합 적용(FAIR+CARE)이 국제적 논의 방향이다. 7장의 프라이버시 논의가 개인 수준이라면, CARE는 공동체 수준의 윤리다. Schwartz & Cook(2장)의 권력 논의가 데이터 거버넌스로 번역된 형태로 읽을 수 있다.

## 발표 문헌 요약

### 📄 논문 요약 1 — Wilkinson et al. (2016), "The FAIR Guiding Principles"

**서지**: Mark D. Wilkinson et al., "The FAIR Guiding Principles for Scientific Data Management and Stewardship," *Scientific Data* 3 (2016): 160018.

**배경과 내용**: 연구데이터의 재사용을 가로막는 것은 데이터의 부재가 아니라 찾기·접근·통합·재사용의 기계적 지원 부재라는 문제의식에서, 학계·출판·기금기관이 합의한 4범주 15원칙을 제시했다. 핵심은 '기계 행동 가능성(machine-actionability)' — 사람이 읽는 문서가 아니라 기계가 찾고 해석할 수 있는 데이터·메타데이터다. FAIR는 특정 기술·표준이 아니라 평가 가능한 원칙 집합이며, 이후 GO FAIR 등 국제 이행 체계와 성숙도 평가 도구로 발전했다.

**아카이브 함의**: 기록의 출처·맥락 기술 전통은 R 원칙의 오랜 실천이다. 반면 PID, 기계가독 형식, API, 명시적 라이선스는 대부분의 기관에서 미비하다. 'FAIR한 아카이브'는 새 시스템 도입이 아니라 이미 하던 기술 작업의 출력 형식을 바꾸는 문제에 가깝다.

### 📄 논문 요약 2 — Carroll et al. (2020), "The CARE Principles for Indigenous Data Governance"

**서지**: Stephanie Russo Carroll et al., "The CARE Principles for Indigenous Data Governance," *Data Science Journal* 19 (2020): 43.

**내용**: 오픈데이터·FAIR 운동이 데이터의 '사람과 목적'을 다루지 않는다는 문제의식에서, 선주민 데이터 주권 운동이 제안한 4원칙: 집단적 혜택(Collective benefit) — 데이터는 당사자 공동체의 발전에 기여해야 하며, 통제 권한(Authority to control) — 공동체는 자신에 관한 데이터의 수집·접근·이용을 통제할 권리가 있고, 책임(Responsibility) — 데이터 사용자는 공동체와의 관계와 혜택 환원에 책임을 지며, 윤리(Ethics) — 공동체의 권리와 복리가 데이터 생애주기 전체의 1차 기준이다. FAIR를 대체하는 것이 아니라 보완하는 원칙으로 제시된다.

**아카이브 함의**: 식민지·과거사·소수자 기록의 데이터셋 개방(collections as data)에서 당사자 공동체 협의 절차를 설계에 내장해야 하는 근거. AI 학습 데이터 제공 논의(토론 Q2)에서 특히 첨예하다.

### 📄 논문 요약 3 — 김학래 (2021), "FAIR 원칙: 데이터 관점의 디지털 아카이브 구현을 위한 고려사항"

**서지**: 김학래, "FAIR 원칙: 데이터 관점의 디지털 아카이브 구현을 위한 고려사항," 『한국기록관리학회지』 21(2) (2021): 155-172. https://doi.org/10.14404/JKSARM.2021.21.2.155

**문제의식**: 국내 디지털 아카이브는 '디지털화'라는 1차 목적은 달성했지만, 자원의 검색과 재사용은 여전히 제한적이다. 저자는 그 원인을 아카이브를 '사람이 읽는 저장소'로만 설계한 데서 찾고, 기계가 읽고 처리할 수 있게 만드는 지침으로서 FAIR 데이터 원칙을 디지털 아카이브에 적용할 것을 제안한다.

**내용**: FAIR의 개념과 국제 동향, 세부 원칙을 개관한 뒤, 기존 FAIR 평가 모델(계획 수립 단계와 적용 단계를 구분)이 개별 원칙의 적용 여부를 판단할 명확한 기준을 주지 못하고, 디지털 아카이브 분야를 위한 평가 기준 논의도 부족하다고 진단한다. 이에 디지털 아카이브를 위한 성숙도 평가 프레임워크를 제안하고, 향후 적용 시 쟁점(기계판독 메타데이터, 식별자, 공통 어휘 등)을 논의한다. FAIR를 '디지털 자원의 탐색·상호 연결·지속 가능성을 위한 틀'이자 '디지털 아카이브 기능에 대한 합의된 프레임워크를 구성하고 평가하는 출발점'으로 자리매김한다.

**의의**: FAIR를 국내 기록학에 본격 도입한 출발 논문. 10.2의 '이미 하던 기술 작업의 출력 형식을 바꾸는 문제'라는 관점의 국내 버전이며, 이 논문의 평가 프레임워크가 후속 실증 연구(요약 4, 11장 요약 3)의 도구가 된다. 실습의 FAIR 자가진단은 이 프레임워크를 간략화한 것이다.

### 📄 논문 요약 4 — 박하람 외 (2024), "FAIR 데이터 원칙을 적용한 국내 디지털 아카이브 평가와 개선 방향"

**서지**: 박하람·강지우·송채은·안지은·이정윤·장소정·조하연·차화준·김학래, "FAIR 데이터 원칙을 적용한 국내 디지털 아카이브 평가와 개선 방향," 『한국기록관리학회지』 24(4) (2024): 113-134. https://doi.org/10.14404/JKSARM.2024.24.4.113

**문제의식**: 디지털 아카이브가 문화예술·과학·비즈니스 등 다양한 분야로 확산되고 웹페이지·게시판·기록관리시스템 등 여러 형태로 구현되지만, 디지털 아카이브의 개념이 불분명하고 기록관리 이론을 적용하는 데 한계가 있다.

**방법과 결과**: 탐색성·접근성·상호운용성·재사용성 관점의 평가 방법론을 제시하고(세부 기준은 공개 저장소에 공개), 국내 디지털 아카이브 261개를 조사해 그중 69개를 상세 평가했다. 결과: 261개 중 74%가 탐색과 접근에 제한이 있었고, 평가 대상 69개의 FAIR 평균 점수는 100점 만점에 50.43점이었다. 특히 상호운용성과 재사용성은 전반적으로 매우 낮은 수준이었다. 저자들은 디지털 아카이브가 단순한 기록 제공 도구가 아니라 기록관리의 연장선에서 역할을 해야 하며, FAIR를 적용한 체계적 개선이 필요하다고 결론짓는다.

**의의**: 국내 디지털 아카이브의 FAIR 수준을 대규모로 측정한 최초의 실증 연구. 10.2에서 과제로 짚은 다섯 영역(PID, 기계가독 메타데이터, API, 라이선스, 데이터로서의 컬렉션)이 실제로 국내에서 가장 취약하다는 점(I·R의 낮은 점수)을 수치로 확인해 준다. 실습의 FAIR 자가진단에서 자기 기관의 점수를 이 평균(50.43)과 비교해 보는 것이 유용하며, 9장 Ramsey의 '착시' 경고(탐색·접근 제한 74%)의 국내 실증 근거로도 읽힌다.

> **💬 모범 답안** — 찬성 논거: ① 존재의 가시성과 내용의 보호를 분리한다 — ICA 접근 원칙이 요구하는 '제한의 투명성'을 구현하며, 이용자는 무엇이 있는지 알고 정보공개청구 등 후속 경로를 밟을 수 있다. ② FAIR A 원칙과 정합. ③ Ramsey의 착시 문제(9장)를 완화 — 숨은 기록도 목록으로는 보이게 된다. 한계: ① 메타데이터 자체가 개인정보·민감정보를 담는 경우(사건명+인명이 들어간 제목)에는 목록 공개도 침해가 된다 → 제목 비식별화 기준 필요. ② 목록만 공개되고 원문 접근 경로가 사실상 막혀 있으면 '형식적 투명성'에 그친다(ICA 원칙 ⑧의 운영상 봉쇄 금지). 결론: 균형점이 될 수 있으나, 메타데이터 비식별화 규칙과 원문 접근의 실효적 경로(열람실·청구 절차·응답 기한)가 함께 설계될 때만 그렇다.

**Q2. 아카이브 데이터가 AI 학습에 쓰이는 것은 FAIR의 성공인가, 새로운 윤리 문제의 시작인가?**

> **💬 모범 답안** — 둘 다이다. 성공의 측면: 재사용(R)의 극대화이며, 기록의 사회적 활용도를 높인다. 윤리 문제의 측면: ① 동의 범위 — 기증자·기록 등장인물은 AI 학습을 예상하지 못했다(목적 외 이용 논점). ② CARE — 공동체 관련 기록의 학습 활용은 통제 권한·집단적 혜택 기준의 심사가 필요하다. ③ 재현의 왜곡 — 편향된 기록(식민지 행정기록 등)으로 학습된 모델은 그 관점을 재생산한다(Huvila 2025의 편향 재생산 경고, 12장). ④ 출처 단절 — 학습된 지식은 원 기록으로의 링크를 잃는다(R의 provenance 원칙과 역설적 긴장). 실무 제안: 학습 허용 여부를 라이선스에 기계가독형으로 명시하고(예: KOGL 유형 + AI 학습 조건 표시), 민감 컬렉션은 데이터셋 단위 심사를 거치게 한다.

## 실습: FAIR 자가진단 워크숍 (과제 4 시작점)

팀별로 프로토타입 대상 아카이브(8장 기획안 기준)를 선정하여 15개 세부 원칙을 3점 척도(충족/부분/미충족)로 진단하고 근거(URL, 스크린샷)를 기록한다. 우선 개선 과제 3개를 고르고, 그중 1개를 12~13장 프로토타입의 데이터 계획으로 연결한다.

### 실습 가이드

아래는 가상 기관을 진단한 **FAIR 자가진단 보고서 작성 예시**다. 실제 과제에서는 8장 기획안에서 고른 아카이브를 진단하고, 모든 판정에 근거(URL 또는 화면 번호)를 단다.

---

**FAIR 자가진단 보고서**

| 항목 | 내용 |
| --- | --- |
| **대상** | ○○ 디지털 아카이브 (가상) — 온라인 목록과 원문 서비스 |
| **진단 범위** | 공개 목록 약 12만 건 중 사진 컬렉션 |
| **진단일 / 진단자** | 2026. 11. 2. / ○○팀 |
| **판정 척도** | ○ 충족 · △ 부분 · × 미충족 |

**1. 원칙별 진단**

| 원칙 | 내용 | 판정 | 근거 |
| --- | --- | :---: | --- |
| **F1** | 전역 고유·영구 식별자 | × | 상세 화면 주소가 검색 세션에 따라 바뀜 [F-1] |
| **F2** | 풍부한 메타데이터 | △ | 제목·일자·생산기관은 있으나 주제어·인물 없음 [F-2] |
| **F3** | 메타데이터에 데이터 식별자 포함 | △ | 관리번호는 있으나 원문 파일과 연결되지 않음 |
| **F4** | 검색 가능한 자원에 등록 | ○ | 자체 포털 검색 가능, 외부 검색엔진에도 노출 |
| **A1** | 식별자로 표준 프로토콜 접근 | △ | 웹 화면은 되지만 식별자만으로는 원문에 닿지 않음 |
| **A1.1** | 개방적·무료 프로토콜 | ○ | HTTPS |
| **A1.2** | 필요한 경우 인증 절차 | ○ | 비공개 원문은 열람 신청 절차 안내 [A-3] |
| **A2** | 데이터가 없어도 메타데이터는 유지 | × | 이관된 기록은 목록에서도 사라짐 |
| **I1** | 형식 언어로 지식 표현 | × | 내보내기 형식 없음(화면 조회만 가능) |
| **I2** | FAIR한 어휘 사용 | × | 자체 분류어만 쓰고 외부 시소러스 연계 없음 |
| **I3** | 다른 메타데이터 참조 | × | 생산기관·인물 전거 연결 없음 |
| **R1** | 정확·충분한 속성 기술 | △ | 사진의 촬영 장소·인물 정보가 절반가량 비어 있음 |
| **R1.1** | 명확한 이용 조건 | △ | 일부 사진에만 공공누리(KOGL) 표시 [R-1] |
| **R1.2** | 상세한 출처 정보 | ○ | 생산기관·이관 경위 기술이 충실함 |
| **R1.3** | 분야 공동체 표준 준수 | △ | 국가 기술 규칙은 따르나 표준 내보내기 형식 없음 |

**2. 진단 요약**

| 영역 | ○ | △ | × |
| --- | :---: | :---: | :---: |
| 찾을 수 있음(F) | 1 | 2 | 1 |
| 접근할 수 있음(A) | 2 | 1 | 1 |
| 상호운용할 수 있음(I) | 0 | 0 | 3 |
| 재사용할 수 있음(R) | 1 | 3 | 0 |

출처 기술(R1.2)은 충실하지만, **기계가 읽고 연결할 수 있는 층위(I 전체, F1)**가 비어 있다. 사람은 찾아 쓸 수 있으나 다른 시스템이 가져다 쓰기는 어려운 상태다.

**3. 우선 개선 과제**

| 순위 | 과제 | 관련 원칙 | 난이도 | 기대 효과 |
| :---: | --- | --- | :---: | --- |
| 1 | 기록 단위 영구 URL 부여 | F1, A1 | 중 | 인용·링크가 가능해지고 다른 개선의 전제가 됨 |
| 2 | 목록 CSV 내보내기·API 공개 | I1, R1.3 | 중 | 외부 재사용과 프로토타입 데이터 확보 |
| 3 | 전 건 이용 조건(KOGL) 표시 | R1.1 | 하 | 재사용 가능 여부를 이용자가 바로 판단 |

**4. 프로토타입 연결**

2순위(목록 개방)를 기다릴 수 없으므로, 공개 화면에서 사진 컬렉션 메타데이터 300건을 수집·정제해 샘플 CSV를 만들어 12~13장 프로토타입에 쓴다. 수집 범위와 이용 조건을 데이터 설명서에 적고, 크롤링 예절(요청 간격, robots.txt)과 저작권을 점검한다.

---

**작성 요령**: 15개 원칙을 모두 판정하되, **× 판정에는 반드시 근거를** 단다. 요약표로 약한 영역을 한눈에 보이게 하고, 우선 과제는 효과와 난이도를 함께 따져 고른다. 마지막 절에서 반드시 팀 프로토타입과 연결한다.
